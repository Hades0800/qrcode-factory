# ERP 單據層級與 MES 對應

來源：ERP 的關聯圖（RECFLOW）與四份真實 QRP 樣本。

## 一、層級

```
訂單 1150911007                       純數字，無字母前綴
└─ 工令 E1150911001                   樞紐：製造與加工都掛在工令底下
   ├─ 製造 F1150911001                一個工令一張製造單
   │   └─ 製造回單 ×8                 完工回報，一次一張
   │      F1150914007  F1150915009  F1150916012  F1150917009
   │      F1150918010  F1150922010  F1150923009  F1150924005
   ├─ 加工 G1150911001                加工單可以多張，有先後道次
   │   └─ 加工回單 ×2   G1150916013  G1150917012
   └─ 加工 G1150911002
       └─ 加工回單 ×2   G1150916014  G1150917013
```

**編號規則**：`<字母><民國年月日><流水號>`。字母是單別（E 工令、F 製造、G 加工），
日期是開單日，所以回單的號碼比母單晚。回單與母單共用同一個字母前綴，
**號碼本身看不出屬於哪張母單**——關聯要靠 ERP 的 RECFLOW，或靠工令 E 往下推。

## 二、幾個要點

**工令 E 是關聯鍵。** 製造單與加工單各自印著自己的單號，單子上沒有指向對方的欄位；
兩者的共同點只有工令單號。已用配對樣本驗證：E1150911001 底下的 G1150911001 與
G1150911002 工令單號相同。

**加工單可以有多張、成道次。** 上例兩張是連續分條：
G1150911001 把 4' 分條成 635mm，G1150911002 再把 635mm 分條成 142mm。
對應 MES 的 `seq_in_order` + `predecessor_id`。

**回單是完工回報。** 一張母單可以有多張回單（上例製造 8 張、跨 10 天），
代表分批完工。這正是 MES 報工要取代或要回寫的東西。

**訂單號碼不一定印在單上。** 上例訂單 1150911007 確實存在，但兩張加工單的
「訂單號碼」欄都是空的（樣本中另一張製造單則填了「EVA口頭指示」這種文字）。
所以不能靠 QRP 取得訂單號碼。

## 三、對應 MES 資料模型

| ERP | MES | 說明 |
|-----|-----|------|
| 訂單 | `Order.poNo` / 客戶訂單 | QRP 上不一定有，需人工或 ERP 介接補 |
| 工令 E | **關聯鍵** | 製造單與加工單靠它串起來；建議獨立成一個欄位並建索引 |
| 製造單 F | 生產模組工單 | 含製造參數（機器SPM、送料設定、模具） |
| 加工單 G | `ProcessOrder` | 多張成道次，`predecessor` 串接 |
| 製造回單 | 報工 / 完工紀錄 | 分批完工，一次一張 |
| 加工回單 | 加工完成紀錄 | 同上 |

## 四、未決

1. **回單要不要匯入？** MES 自己就會產生完工紀錄。若 ERP 的回單仍是正式憑證，
   要決定是「MES 回寫產生回單」還是「兩邊各記各的」。前者才不會有兩套數字。
2. **回單的 QRP 樣本還沒拿到**，欄位配置未驗證。解析器目前認得出單別並發警告，
   但不保證欄位抓得對。
3. 加工單的道次順序，ERP 有沒有明確欄位？目前只能從「前一張的產出＝後一張的領用」推。
